## 1. 一句话
`lib/engine.js` 中「功能牌不改变门槛牌」的规则实现存在状态空洞：**桌面上只有功能牌时 `topCard === null` 但 `tablePile.length > 0`**，下一次 `computeLegalMoves()` 读取 `room.topCard.kind` 抛 `TypeError`，导致该房间**此后任何操作（含超时托管）都抛异常**，无法推进到结算，唯一出路是全员离开。

## 2. 严重度依据
- **游戏必现级可达**：GDD v1.1 §6.3 明确「一轮的第一张牌（桌面为空）可出任意牌（含功能牌）；此时 2 仅反转方向，A 视为白打一张」。而 `computeLegalMoves()` 的 `actions` 在**任何**桌面状态都包含手上所有 A/2，因此这是**前端会正常高亮、玩家会正常点击的合法操作**。
- **不可自愈**：与 BUG-001 不同，本缺陷不会在下一步恢复。崩溃发生后：
  - 当前玩家无法出牌（`playCard` → 内部先调 `computeLegalMoves` → 抛错）；
  - 当前玩家无法收牌（同上）；
  - 超时托管**没有任何定时器**（`sendTurn()` 在调度前就抛异常），因此挂机/断线兜底**全部失效**；
  - `nextRound` 静默无效（phase 仍是 `playing`）；
  - 房间永久驻留内存（全员掉线后才由 GC 回收）。
- **原 67 项测试全绿也无法发现**：测试覆盖的都是「桌面非空且 topCard 非空」的局面。

## 4. 复现步骤（协议层，无需浏览器）
前置：3 人房，全员准备，房主开局（`phase=playing`、`tablePile=[]`、`topCard=null`）。

1. 让当前玩家手牌为 `[2♠(action), 4♥(monster)]`，其余保持默认。
2. `computeLegalMoves()` → `{opening:true, beats:[['4♥']], actions:['2♠']}` ← 2 被判定为合法可出。
3. 客户端发 `playCard {cardIds:['2♠']}`。
4. **预期**：`2` 被消耗、方向反转、下家收到 `yourTurn`、房间继续。
5. **实际**：
   - 出牌者收到 `error {code:'ERROR', message:"Cannot read properties of null (reading 'kind')"}`（前端 toast「操作失败」）；
   - 下家**收不到** `yourTurn`；
   - `room.tablePile.length=1`、`room.topCard=null`、`currentPlayerId` 已切到下家、`direction=-1`；
   - net 层**存活托管定时器 = 0**（无 `30000` / `1500` / `8000` 中任一）。
6. 继续验证卡死：下家发 `playCard` → `error {code:'ERROR', 同上}`；下家发 `pickUp` → 同上。
7. 等待 35s（> `turnTimeoutMs=30000`、> `pickupDelayMs=1500`）→ 桌面不变、`phase` 仍 `playing`、无任何 `yourTurn` / `gameEnd`。
8. 房主发 `nextRound` → 无 error、`phase` 仍 `playing`（静默无效）。

> 实测输出见 `production/qa/gate-0-report.md` 附录 A（探针 `.workbuddy/qa-probe-p0.js`，使用生产默认定时参数）。

`A`（跳过）同理：`first.rank === 'A'` 分支同样不设置 `topCard`，开轮打 A 也会落入同一空洞。

## 6. 修复建议（供 engineering-lead 决策，QA 不直接改产品代码）
- **根因修复（必需）**：`computeLegalMoves()` 的 opening 判定应同时考虑门槛牌是否存在，例如
  `const effectiveTop = room.tablePile.length === 0 || !room.topCard ? null : {...}`。
  语义上与 GDD §6.3「门槛牌不变 / A 视为白打一张」一致：桌上只有功能牌时下家仍可任意出牌；`pickUp` 时这些功能牌仍随桌面一起进败牌堆（§10 Q5 不受影响）。
- **防御性兜底（建议一并做）**：`net/net.js` 两处 `catch (e) {}` 至少 `console.error` 记录 `roomCode / pid / e.message`，并把异常路径转成明确的 error code（而非 `ERROR`）；否则同类崩溃会继续以「静默卡局 + 操作失败」的形式出现。
- **测试补齐**：`test/engine.test.js` 增加 `lib` 层用例（开轮打 A / 打 2 / 连续两个 2 后 computeLegalMoves 不抛错 / 开轮打功能牌后收牌正常）；`test/net.test.js` 增加协议层用例。
